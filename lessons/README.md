# lessons/ — 審查經驗記憶庫

這裡累積合約審查過程中「修正過的錯誤」與「確認有效的做法」，讓之後的審查（不論是人或 AI 助手）不再重蹈覆轍。

## 撰寫規範

1. **一個教訓一個檔案**，檔名 `YYYYMMDD-短標題.md`（日期為首次記錄日）。
2. **第一行必須是一行摘要**（以 `# ` 開頭），讓人掃過檔名與首行就能決定要不要展開。
3. 內文固定三段：
   - **情境**：發生了什麼（哪份合約、哪條規則、哪個誤報／漏報）。
   - **做法**：修正後的做法，或被驗證確認的做法。
   - **為什麼重要**：不記下來會付出什麼代價。
4. **不重複**：已寫在程式碼註解、規則檔 message、或其他 lesson 裡的內容不再抄一份；lesson 記的是程式碼放不下的脈絡與判斷理由。
5. **更新優於新增**：同主題有既有 lesson 時直接更新它（可改標題與內容），不要開新檔。
6. **錯了就刪**：發現某個 lesson 的結論是錯的，直接刪檔或改寫，不保留錯誤結論。

## 與審查規則的關係

lesson 若能落地成規則，優先落地（`python review.py add-rule` 或直接編輯 `rules/*.yaml`），lesson 只保留規則無法表達的背景與理由。
